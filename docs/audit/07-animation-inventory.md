# 07 — Animation inventory

## Scope and evidence standard

This is a static-source inventory of production motion; Storybook examples are excluded from the inventory. No build, browser session, or animation playback was run because the audit brief forbids commands that may generate files. Timing and state-machine claims below are therefore source-confirmed, while perceptual quality, browser support, and frame-rate claims remain runtime questions.

The shared duration tokens are `durationXS` 200 ms, `durationS` 300 ms, `durationM` 400 ms, `durationL` 600 ms, and `durationXL` 800 ms in `app/components/theme-provider/theme.js:4-56`. The CSS motion gates are declared in `app/global.module.css:7-8`; Framer Motion 11.0.5, Three 0.161, and three-stdlib 2.29.4 are declared in `package.json:25,32-33`. **Classification: CONFIRMED BY LOCAL REPOSITORY.**

## Motion substrate

- `Transition` is the reusable CSS-state bridge. It wraps Framer Motion `AnimatePresence`/`usePresence`, emits `entering`, `entered`, `exiting`, and `exited`, forces a reflow, and completes phases with caller-supplied timeouts in `app/components/transition/transition.jsx:1-102`. It clears opposing timers when state changes. Consumers include `Intro`, `ProjectSummary`, `Profile`, `ProjectBackground`, `Navbar`, `Input`, `Button`, `Code`, `Contact`, Earth/Armor loading states, and error layouts. **Classification: CONFIRMED BY LOCAL REPOSITORY.**
- Global `fade-in` and left-to-right/right-to-left `reveal` keyframes live in `app/global.module.css:51-80`. Component CSS combines those keyframes with `data-status`, `data-visible`, and `data-loading` attributes. **Classification: CONFIRMED BY LOCAL REPOSITORY.**
- Framer Motion springs and `animate()` drive decoded text, device entrance/lid movement, pointer tilt, the Earth sequence, and carousel interpolation. The WebGL owners render either continuously or only when a spring/resize/load event asks for a frame. **Classification: CONFIRMED BY LOCAL REPOSITORY.**
- `Transition` itself does not inspect `prefers-reduced-motion`; reduction is delegated to each component's CSS or `useReducedMotion()` logic. Consequently, reduced-motion coverage is not uniform. **Classification: CONFIRMED BY LOCAL REPOSITORY.**

## Required-effect traces and preservation boundaries

### Hero block cover and approved changing copy

The reusable chain is `Intro` → `Transition` status → `.word[data-status]` → `.word::after` → global `reveal`. The accent block is not a canvas effect and is independent of the hero sphere. Changing text is data-driven by `config.disciplines` and keyed `Transition` instances. **Classification: CONFIRMED BY LOCAL REPOSITORY.**

The later approved copy (`I GET`; `AUTOMATION DONE.`, `FUNNELS DONE.`, `WORKFLOWS DONE.`) is supplied by the audit brief, not the repository. Adapting it at the current data/render seam while retaining the cover mechanics is technically plausible but remains a future target. **Classification: STRONG INFERENCE.**

The 5-second interval is longer than the 3-second enter timeout, while exit lasts 2 seconds. Whether the approved longer phrases wrap, collide, or feel legible at 400/696 px cannot be established from static source. Verify in both themes, 320–400 px widths, short landscape, reduced motion, and while toggling theme. Human motion review is required. **Classification: UNRESOLVED / NEEDS RUNTIME VERIFICATION.**

### Connected-page/window behavior

The repository explicitly requests the framework view-transition option on internal link paths, while independently fading the entire outlet and showing a progress bar. There are no repository-defined shared-element names, pseudo-element animations, or Contact-specific connected-window implementation. **Classification: CONFIRMED BY LOCAL REPOSITORY.**

It is a strong inference that supported browsers receive the framework/browser default document transition and unsupported browsers receive ordinary navigation, but that behavior comes from the installed Remix/React Router runtime rather than code in this repository. Safest later verification: record navigation among `/`, `/contact`, and a project route in current Chrome/Firefox/Safari with view transitions enabled/unsupported, keyboard focus logging, reduced motion on/off, and slow network simulation. **Classification: STRONG INFERENCE.**

The visual relationship among native snapshots, the 400 ms outlet fade, the 500 ms progress threshold, scroll restoration, and focus after navigation is unresolved. Human review is required before calling the result a preserved “connected window.” **Classification: UNRESOLVED / NEEDS RUNTIME VERIFICATION.**

### Decorative large-text depth

Current homepage depth is not a shader or mask. One SVG is painted before the later model sibling; its whole opacity is 0.7 in light theme or 1 in dark theme, and the model visually occludes it. Earth labels provide a second, unrelated technique: each whole DOM label receives `data-occluded` using a camera-distance heuristic and becomes opacity 0.2 in `app/routes/projects.smart-sparrow/earth.jsx:154-187` and `earth.module.css:52-80`. Neither technique changes only the portion of a word behind an object. **Classification: CONFIRMED BY LOCAL REPOSITORY.**

No source currently contains the future words SYSTEM, GAPS, CASE STUDY, or PROFILE, and no reusable partial-word mask/duplicate-layer API was found. The locked future requirement therefore needs an explicit technique decision after object geometry and responsive overlaps are known. Do not flatten the future word to one opacity and do not claim the current SVG fade already meets the requirement. **Classification: CONFIRMED BY LOCAL REPOSITORY.**

Whether sibling stacking can be extended with duplicated front/back text, CSS masking, or a canvas depth texture without damaging the laptop's transparent canvas and pointer motion cannot be selected safely from this audit. Prototype those approaches in an isolated later phase and compare contrast at every breakpoint; Daniel/creative review is required. **Classification: UNRESOLVED / NEEDS RUNTIME VERIFICATION.**

## Timing, cleanup, and reuse risks

- Caller timeouts must stay synchronized with CSS duration/delay. `Transition` does not derive completion from `transitionend`/`animationend`; changing CSS without its timeout can unmount early or retain invisible DOM. **Classification: STRONG INFERENCE.** Evidence: `transition.jsx:53-98` and the 3,000/2,000 ms hero values at `intro.jsx:91-95`.
- `DecoderText` cancels its spring subscription but not its delayed async start; WebGL `Device`, Earth, Armor, and Carousel have separate async lifetime gaps documented in 09. **Classification: CONFIRMED BY LOCAL REPOSITORY.**
- The project model's `onLoad` is called per `Device`; the phone preview passes two devices but shares one `modelLoaded` flag, so the loader/decorative reveal can complete after the first device rather than both. **Classification: CONFIRMED BY LOCAL REPOSITORY.** Evidence: `project-summary.jsx:35,46-62,141-166` and `model.jsx:498-517`.
- Earth passes the entire `Transition` render payload to a variable named `visible` instead of destructuring `{ visible }`, then writes that object to `data-visible` (`app/routes/projects.smart-sparrow/earth.jsx:675-683`). The matching CSS requires the literal string `'true'` (`earth.module.css:8-19`), so the delayed Earth loader cannot enter its intended visible rule. **Classification: CONFIRMED BY LOCAL REPOSITORY.**
- Static source cannot establish frame pacing, cumulative layout shift, GPU memory, animation contrast, or whether browser-native route snapshots visibly double-fade. Use Performance/Rendering traces on representative desktop, mid-range Android, iOS Safari, reduced motion, coarse pointer, and WebGL-unavailable configurations. **Classification: UNRESOLVED / NEEDS RUNTIME VERIFICATION.**
