# Reuse, adapt, replace matrix

## Purpose and decision rule

This matrix evaluates the current Hamish Williams repository as the technical foundation for the future DonewithDan portfolio. It is not an implementation specification. A difficult adaptation is not classified for replacement merely because replacement would be easier. “Replace” and “Remove” are used only where the approved destination explicitly rejects the current content or structure.

The disposition vocabulary is the one required by the audit brief:

- Reuse unchanged
- Reuse with content changes
- Adapt structurally
- Replace
- Remove
- Unresolved

## Matrix conclusion

- CONFIRMED BY LOCAL REPOSITORY — the highest-value reuse is the Remix root shell, theme-token pipeline, shared Transition/DecoderText/Image primitives, persistent navigation split, native route-transition opt-in, project layout, and WebGL laptop.
- STRONG INFERENCE — adapting these seams section-by-section will preserve more verified behavior than replacing the application shell, because the same primitives already serve multiple route families and responsive states.
- UNRESOLVED / NEEDS RUNTIME VERIFICATION — SYSTEM content/motion; GAPS illustrations/stack implementation; tool-strip assets; exact decorative-depth implementation; HaircutDone media/route slug; Contact delivery; hosting; and legacy-route disposition require supplied inputs or later runtime/human verification. Frozen GAPS/tool-strip behavior and the required decorative-depth result are not open decisions.
